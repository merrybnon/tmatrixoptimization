## [Unreleased]

### Added

- `src/tm_ml/models.py`: the model, finished and committed. Equivariant transformer encoder over 20 node tokens with an additive per-head attention bias built from edge features; a decoder whose few equivariant layers mix the latents before an asymmetric pair MLP, then `-inf` on the diagonal *before* the row softmax so every output is a valid transition matrix by construction; and an invariant property predictor. Per-row KL reconstruction, per-group prior KL, and a no-grad log-space reconstruction diagnostic, with the four zero-diagonal nan traps handled where `architecture.md` says they detonate.
- `src/tm_ml/models.py`: `NodePool`, behind a `pooling` config field with `mean`, `deepsets` (default) and `attention` modes. The predictor was `rho(mean(z_i))` with phi the identity, which Wagstaff et al. put below the representable bound at n = 20 against d_latent = 8; `deepsets` puts phi at width 64 and clears it, so `attention` becomes a claim about inductive bias to be settled by sweeping rather than by argument.
- `src/tm_ml/config.py`: defaults in code and sweeps in YAML, any field given a list becoming an axis and several lists the cartesian product. Everything checkable without the data fails at DAG-build time, including the guardrail that refuses to sweep a field that does not reach the run name — the one failure mode that produces wrong results rather than no results, since every point would land in one directory. Imports nothing heavier than yaml and pathlib.
- `src/tm_ml/config.py`: `lr_schedule` (cosine, exponential), `lr_warmup_epochs` and `gamma_warmup_epochs`, all off by default, with `lr_at` and `loss_weight_at` as pure functions so the resolved config stays the only description of a run. `lr_final_frac` is inert without a schedule, so it is coerced to a frozen value and sweeping it against a constant rate is refused.
- `src/tm_ml/paths.py`: run names carrying only the fields that differ from a **frozen** `NAME_BASELINE`, kept separate from the defaults so a default can move without renaming anything. Two registries make the invariant mechanical: a determining field with no abbreviation, or no baseline entry, makes `run_name` refuse rather than silently omit it. Plus `config_guard`, which catches a changed config that does not reach the name — under Snakemake a checkpoint newer than its inputs otherwise looks like a finished job.
- `src/tm_ml/datasets.py`: splits and the target transform. The log is always taken; standardizing is optional and fitted on the **training split alone**, which is why it lives here rather than in the model — the model sees a batch and has no idea which examples are training data. The constants ride in the checkpoint so evaluation reports in real decay-exponent units.
- `src/tm_ml/device.py`: `gpu: auto` resolves to an explicit `cuda:<i>` by most-free memory, which matters on a box whose three A100s differ by an order of magnitude in free memory. Advisory claim files for concurrent launches are documented and not yet written.
- `src/tm_ml/train.py`: three-layer resolution (defaults, sweep YAML, explicit `--set`), the loop, and one run directory holding checkpoint, history, both configs and provenance. Checks the zero diagonal, the row sums and the finiteness of every loss term before the first step, which `architecture.md` asks for because the failure mode is silent nan propagation.
- `src/tm_ml/evaluate.py`: test-split metrics in four groups — the property against a train-fitted mean baseline, reconstruction in KL and log space with a by-magnitude table, validity as constraints rather than scores, and latent structure (active units, PCA against the posterior noise floor, Gaussian total correlation against its null bias, and the ELBO-surgery mutual-information bound). Node latents are pooled as `(N x 20, d)` rather than flattened per graph, because coordinate k means the same thing for every node while node 3 of one matrix has nothing to do with node 3 of another.
- `src/tm_ml/visualize.py`: four figures per run — training curves, property predictions, reconstruction heatmaps with the error-by-magnitude curve, and the latent spectrum — each stamped with a provenance footer. One measure per axis and no dual-axis panel; a single-hue ramp for magnitude and a diverging pair with a neutral midpoint for signed error.
- `src/tm_ml/benchmarks.py` and `docs/benchmarks/runs.csv`: a **curated** ledger rather than a mirror of disk. A hand-written row passes through, a hand-written note is never overwritten, and a row survives the deletion of its run directory, because the ledger records what was tried. Runs are found by recursing for run markers, so a `parent_path` of any depth is visible.
- `src/tm_ml/config.py`, `paths.py`: `parent_path`, so runs file into folders under `results/`. Non-determining — filing is not science — so it stays out of the run name and out of `config_guard`, and a run can be moved between folders without being locked out of its own directory.
- `workflow/Snakefile`: the full chain. With no config it ingests every drop and stops; given a sweep it expands it, ingests only the drops those runs need, and chains train, evaluate, visualize and benchmarks per point. Sources are deliberately not inputs to `train` (a docstring fix would otherwise invalidate every trained run) but are inputs to the cheap stages. `config.json` is deliberately not a declared output and the ledger is declared with `update()`, both because Snakemake deletes declared outputs before running a job — which would defeat `config_guard` and destroy the hand-written rows respectively.
- `config/sweeps/latent.yaml` and `config/sweeps/smoke.yaml`: the latent-capacity sweep and a short plumbing sweep.
- `tests/`: `test_models.py`, `test_config.py`, `test_datasets.py`, `test_evaluate.py`, `test_visualize.py`, `test_benchmarks.py` and a shared `conftest.py`, 158 tests. The equivariance claims run in float64 because a 1e-15 residual is the point; the stage tests redirect both the processed-data root and the results root into tmp so train, evaluate and visualize run end to end without touching the repo.
- `docs/notes/repo_structure.md`: the layout and the reasoning behind it — why raw drops are committed while derived output is not, the per-level `!.gitkeep` spelling, ingest as the sole reader of a raw drop, drops discovered rather than enumerated, and the per-module responsibilities. Records the `config/data.yaml` decision, which was implemented in code on 09-14 and never written down.
- `docs/notes/GNNsources.md`: Wagstaff et al., *On the Limitations of Representing Functions on Sets* (ICML 2019), the bound that sizes the pooling, placed beside Deep Sets and Set Transformer.

- `docs/notes/permutationsandlatent.md`: the latent-structure decision worked through, covering the group action on each object in the architecture, a per-component equivariant/invariant ledger, why the reconstruction is equivariant while the loss is invariant (which is what makes matching unnecessary), a worked 3-node relabelling example, the orbit answer to whether one latent can represent all 20! labellings, and the hybrid graph-level latent.
- `docs/notes/architecture.md`: ascent equivariance. The predictor is invariant, so ∇ŷ|_(PZ) = P · ∇ŷ|_Z and latent gradient ascent commutes with relabelling — an optimized landscape cannot depend on how its input happened to be labelled. Carries the test procedure, which must run with sampling off, since equivariance of a sampled z holds only in distribution.
- `docs/notes/GNNsources.md`: a `## Reading order` section with two paths — the narrow one for why a transformer encoder and a GNN are the same thing here, and a general ten-item order into the field. Four new entries: Hamilton's *Graph Representation Learning Book* and Kipf & Welling's GCN paper, both absent and both needed for basic-level grounding; Edwards & Storkey's *Towards a Neural Statistician*, the two-level latent for exchangeable sets behind the hybrid; and Battaglia's global attribute `u`, folded into the existing entry as the mechanism that makes a broadcast invariant preserve equivariance.

### Changed

- `src/tm_ml/train.py`: model selection now ranks on the loss recomputed at the **configured** beta and gamma rather than at each epoch's own. Under warmup those are different objectives, so an early epoch scored well largely because beta was still small — the first 300-epoch run kept its epoch-10 checkpoint for exactly that reason. `history.csv` carries both: `total` is what was optimized that epoch, `score` is what ranks.
- `workflow/Snakefile`: every stage runs under `python -u`. Python block-buffers stdout when it is a pipe, so the `tee` that was supposed to show live progress left a 300-epoch log empty until the job exited.
- `config/sweeps/latent.yaml`: learning-rate decay restored after a matched-pair test. Decay earns its place on stability, not accuracy — same config and seed, the last fifty epochs show 7x the standard deviation and 9x the range without it, so which checkpoint survives depends on where the oscillation lands.
- `README.md`, `CLAUDE.md`: dropped the `config/data.yaml` references. Both advertised a file that was decided against on 09-14 and never created; `ingest.find_source` plus `meta.json` took over its two jobs. `CLAUDE.md` also gained the `evaluate.py`, `visualize.py` and `benchmarks.py` modules its own pipeline description already named.

- `docs/notes/GNNsources.md`: the GE-VAE entry (arXiv 1910.08057) was misfiled beside PIGVAE and GraViti as though it were a graph-level method. Its latent is |V| x P, node-level, so it is the family we already chose reached independently. Rewritten with what the model actually is and the three reasons it is ruled out — a Laplacian-eigenmap encoder that reintroduces the canonicalization discontinuity in spectral form, a symmetric z_iᵀz_j that cannot represent our directed edges, and binary undirected topology whose sparse-likelihood contribution is worthless on a dense 20-node digraph.
- `WORKLOG.md`: the next-steps block reformatted for `~/bin/nextsteps`, which parses `/^### Next steps/` and treats a blank line as the terminator. The previous `### Where we left off` heading with a separate `Next steps:` line and an intervening blank matched nothing, so the tool returned empty.


## [0.1.0] - 2026-09-14

### Added

- Repository scaffold: `config/`, `workflow/`, `src/tm_ml/`, `data/`, `results/`, `tests/`, `docs/`. Raw drops under `data/raw/` are committed so a clone carries the exact bytes a run trained on; `data/processed/` and `results/` are derived and gitignored, which needs the per-level `!.gitkeep` spelling in `.gitignore` because a bare `data/` makes git skip the directory entirely and silently ignore the negation.
- `pixi.toml` with a base environment and an `ml` feature on the `linux-64-cuda` platform, which is what makes conda-forge resolve CUDA-enabled pytorch — `pytorch = { build = "cuda*" }` will not solve on plain `linux-64`. Split rather than collapsed so the base environment stays installable on a machine without CUDA. `PYTHONPATH` is set to `$PIXI_PROJECT_ROOT/src` in `[activation.env]`, so `python -m tm_ml.x` resolves from any directory and the Snakefile imports the package directly instead of the `sys.path.insert` hack the sibling repo needs. `bioconda` stays in the channel list because `snakemake-minimal` lives there, not on conda-forge.
- `src/tm_ml/ingest.py`: the only code that reads a raw drop. Stacks the source's object array of separate 20x20 arrays into one contiguous `(N, 20, 20)` block, validates, and writes `matrices.npy`, `targets.npy` and `meta.json` to `data/processed/<drop>/`. Validation is fatal and names the offending index — square and mutually consistent shapes, row sums within 1e-6 of 1, no non-finite or negative entries, matching lengths. Checked in float64 before the float32 cast, so the tolerance tests the drop rather than our own rounding. Targets are written exactly as received; normalization belongs to the dataset or the model, so changing it later costs no re-ingest.
- `workflow/Snakefile` with the ingest rule. The drop's `.npz` reaches the rule through an input *function* calling `ingest.find_source`, so the file is a real dependency with real mtime tracking rather than a hardcoded name, and an unknown drop fails at DAG-build time naming the drops that do exist. Drop directories are globbed at parse time, so adding one makes it a target with no edit here.
- `tests/test_ingest.py`, 18 tests, run with `pixi run test`. Four cover the happy path against `tests/fixtures/tiny.npz` — a committed 30 KB slice of the real drop in the same object-array layout, so the tests exercise the real code path and need no access to the full data. The rest assert on failure *messages*, not just exception types, and include a transposed drop: Tom's own script sorts by column sum while the data is row-stochastic, so both conventions are already in play and a transposed future drop would otherwise train silently on garbage.
- `docs/notes/architecture.md`: the design, ahead of the code. Masked row softmax before normalization, per-row KL reconstruction, permutation equivariance built in rather than canonicalized, node-level latents. Carries the four places the structural zero diagonal produces NaN rather than a violated constraint.
- `docs/notes/GNNsources.md`, `NetworkDiversity.md`, `miscSources.md`: annotated reading list, the domain literature on network structure and genetic diversity, and everything else, each entry noting what it is and why it bears on this project.
- `data/raw/Tom1000/Analysis_Results.npz`: 1000 20x20 row-stochastic matrices with paired decay exponents.
